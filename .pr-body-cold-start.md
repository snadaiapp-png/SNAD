## Summary

Adds cold-start forensic instrumentation for Render Free-tier profiling. **No business-logic changes, no security changes, no DB changes.**

## Background

The previous true cold-start test (PR #915 acceptance) revealed:
- Render Free cold start takes **125–282 seconds** (variable)
- The 125s BFF auth budget is exceeded when cold start > 125s
- We have **no visibility** into where the startup time is spent

The Dockerfile documents: *"The app takes 3-18 minutes to start depending on Flyway and DB connection."*

## Changes

### 1. `SanadPlatformApplication.main()` — attach `BufferingApplicationStartup`

```java
app.setApplicationStartup(new BufferingApplicationStartup(10_000));
app.addListeners(new StartupTimelineLogger());
app.run(args);
```

Spring Boot will now buffer every startup step (bean instantiation, auto-config, Flyway, Hibernate, Tomcat, security filter chain, etc.). Capacity 10k is sized to hold the full startup tree (~5k steps observed). Overhead is ~1-2 us per step, total <500 ms even on Render Free's slow CPU.

### 2. New `StartupTimelineLogger` (registered via `addListeners`)

Registered programmatically (not as `@Component`) so it can observe the **early** lifecycle events that fire BEFORE the `ApplicationContext` exists:

- `ApplicationStartingEvent` — JVM start, before any bean
- `ApplicationEnvironmentPreparedEvent` — env + post-processors
- `ApplicationPreparedEvent` — bean definitions ready
- `ApplicationStartedEvent` — context refreshed, beans instantiated
- `ApplicationReadyEvent` — all runners complete, app ready

On `ApplicationReadyEvent`, dumps:

1. **`[STARTUP] TIMELINE`** — total events + timeline start instant
2. **`[STARTUP] SUMMARY`** — 5-phase duration breakdown
3. **`[STARTUP] TOP_30_SLOWEST_STEPS_BY_SELF_DURATION`** — each step with total_ms, self_ms, children count
4. **`[STARTUP] CATEGORY_SUMMARY`** — aggregation by step-name prefix

All output goes to the `SANAD-STARTUP` logger so it appears in the existing `logback-spring.xml` prod JSON console appender and Render's deployment logs.

## Risk Assessment

| Risk | Mitigation |
|------|------------|
| Listener fires on every cold start | Overhead <500 ms total, one-shot on ApplicationReadyEvent |
| Buffer overflow | Capacity 10k >> observed 5k; overflow drops oldest silently |
| Logs too verbose | Output is INFO on SANAD-STARTUP logger |
| Sensitive data leaked | Step names are Spring framework internals (no env values, no secrets) |
| Compilation failure | Code targets Spring Boot 3.5.6 API verified by bytecode inspection |
