## §1 منهجية التحقيق

1. **الجرد**: `GET /pulls?state=all` بصفحات كاملة (1240 PR) — كل الطلبات المفتوحة (67) والقوائم الكاملة للمغلقة.
2. **الاختيار للعمق**: الـ67 المفتوحة (كلها، بما فيها الـDrafts) + المغلقة-غير-المدمجة ذات الصلة (G1: #1368 #1372 #1380 #1386 #1413 #1415).
3. **جلب كل الرؤوس محليًا** (`refs/pull/N/head`) وحساب merge-base لكل طلب.
4. **مقارنة ثلاثية آلية لكل طلب** (منهجية موحّدة): لكل ملف متغيّر من قاعدة الدمج: مطابقة blob مع main ⟸ *مطابق تمامًا*؛ غياب عن main ⟸ *فريد*؛ والا دمج ثلاثي `git merge-file` (base/ours=main/theirs=PR) — ناتج الدمج == main بايتيًا ⟸ *مستوعب*؛ الا ⟸ *متبقٍّ* مع حفظ الـresidual diff للفحص اليدوي.
5. **قراءة يدوية hunk-by-hunk** لكل متبقٍّ في المسارات الحساسة (أمنيًا) + فحوصات نقاط دلالية على main لكل نية (نصوص مفتاحية، هجرات، أسماء أصناف، سجلات runs).
6. **فصل صارم لأدلة CI**: فحص runs على رأس كل PR بـhead_sha الصريح، ولا يُنسب نجاح main إلى فرع أي PR.

**قيود بيئة موثّقة**: لا Maven ولا psql محليًا في بيئة التنفيذ — لذا كان CI الحي على GitHub (بما فيه تشغيلات اليوم على `main@b95415fe` وعلى رأس PR النقل #1420) هو سلطة تنفيذ الاختبارات، وكل ادعاء نجاح اختبار في هذا التقرير مرتبط بـrun فعلي بمعرّفه.
